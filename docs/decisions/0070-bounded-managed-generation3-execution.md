# ADR-0070: Bounded Managed Generation3 Execution

Status: Accepted; source tests do not qualify activation or release.

Date: 2026-10-25. Decision owner: Product owner.

## Scope and owner

Refine ADR-0037's managed write inventory and ADR-0045's explicit generation
selection only for managed profile3/Cohort2 to profile4/Cohort3, and its selected
original rollback. Preserve accepted ADR-0032 and ADR-0037 bytes. ADR-0052 and
ADR-0056 remain their historical proposed decisions; this decision does not
accept their wider proposals or obsolete package/version reservations.

The existing Docs Protocol Agent Teams consumer-integration owner owns projection,
preparation, finalization and activation. Its private helpers share existing
Repository Mutation leases, claims, known-file plans, journal recovery and receipt
validation. There is one repository mutation writer. This adds no package, graph
node, generic migration manager, registry version or qualification receipt version.
Central continues to own lifecycle, enrollment, source admission and CANARY.

## Exact transition

1. Select an explicit target generation from the current protected Central main.
   Generation3 validates the closed record, policy, complete event chain, lifecycle
   and actual canary enrollment. Re-read the exact authority after staging and
   before publication. A separately retained external successor controller runs
   on actual Node24.21.0; the immutable stable31 adapter0.3.2 cannot learn this
   executor from a new central edge. Published adapter0.5.5 also lacks this path.
2. Keep five package coordinates and three root development dependencies. Append
   only stable31's exact historical projection and content-addressed Skill/caller
   bytes through the existing asset generator; retain every existing bundle.
   The source must pass its exact historical managed-asset check and unchanged
   source Git revision/tree proof before staging.
3. The finite write inventory adds `.node-version` to the previous eight-file
   maximum. Permit only managed integration schema3/4 and Cohort binding,
   `.node-version`, root `packageManager` and `engines.node` runtime transitions
   in addition to existing owned pins, assets and workspace exclusions. Validate
   every preimage against immutable Git bytes/mode and every target against
   deterministic owner projections. Preserve foreign lock policy, comments,
   importers and dependency graphs. Portable profile3-to4 remains separate.
4. Receive explicit Node24, Node26 and Corepack entrypoint paths. Observe the
   physical source24.21.0 and target26.11.1 on Linux/x64, and actual pnpm against
   the exact root pin. Target pnpm is11.20.0. Reject wrong/missing runtimes before
   installation; no engine/platform spoof or fallback. Cold finalize and inverse
   restore re-observe the selected runtime/manager before CAS with network disabled. Activation and source
   restoration use frozen offline installation, ignored lifecycle scripts and
   the existing process owner. Windows mutation remains unsupported.
5. Prepare only in disposable Git-archive copies. The target's installed CLI
   performs actual plan/apply/check. Before any consumer mutation retain a
   separately selected canonical preparation, with digest, outside the consumer
   and controller installation. Its closed generation2-to3 family records the
   source Git/tree/full-file inventory, consumer identity, exact controller and
   kernel versions/build identities, exact plan and original/target bindings.
   The older literal generation1-to2 preparation/proof family is unchanged.
6. Finalize selects that preparation by path and separately retained digest.
   Validate consumer identity, exact retained controller/kernel builds, unchanged
   source Git, complete original or target images and fresh protected authority.
   Apply through the existing RM claim, then persist the observed receipt before
   target activation. A cold controller can resume after publication, including
   the window before receipt persistence: an idempotent RM `already-satisfied`
   receipt is observed honestly and never presented as original write ownership.
   Completion is retained only after real target activation/check and final
   source/authority/image revalidation. The public execution envelope remains1.
7. If live activation fails, automatically compensate only an authentic receipt
   in which this attempt replaced every selected file. A cold observation does
   not grant that ownership. The original same-HEAD generation3-to2 route keeps
   its original consumer identity and source Git checks unchanged.

   A later committed/merged consumer rollback uses a separate current-target
   admission, not a cast of the original proof. Explicitly select CURRENT clean
   Git HEAD/tree; prove original-source ancestry, the committed exact Cohort3,
   all managed postimages, fresh current root/repository identity, exact retained
   controller/kernel builds and the current qualified stable31 rollback edge.
   An arbitrary descendant or old proof alone grants no authority. Retain a
   closed current selection before effects and rebuild its inverse CAS plan from
   admitted current bytes. Its fresh inventory preserves unrelated Host files;
   it does not replace the whole repository with an old snapshot.

   Reverse overlapping Host Stack/scripts/quality changes through their own
   owner on the UNMERGED rollback PR branch before this admission. Whole-file
   package/lock/workspace/profile images with foreign changes refuse overwrite;
   the managed owner does not merge or reverse Host fields. These preparatory
   Host commits need not be merged separately. Full consumer CI owns readiness
   after both reversals. This adds no Host patch framework.

   Runtime/manager preflight with network disabled occurs before inverse CAS.
   A separately selected current-intent digest permits cold resume after inverse
   publication before the real Node24 source installation/check. Unknown
   lineage, stale HEAD/tree or selection, dirty initial state, mixed/foreign
   managed images or changed unrelated files refuse. Supported suspended sources
   can authorize restoration without becoming newly selectable; SUPERSEDED
   support must remain unexpired. After rollback is committed, its old current
   selection is stale. The public restored/receipt execution remains schema1.

8. Ordinary profile4 check/plan/apply uses the actual Cohort3 manifest planner and
   canonical state3 projection without a cast to generation2 or a historical
   catalog. Unknown managed bytes remain blocked. Direct synchronous2-to3 or
   unselected3-to2 upgrade refuses before staging/publication. A different future
   Cohort3 successor is outside this finite retained controller.

## Validation and activation boundary

Maintained tests exercise real Git source evidence and real RM CAS, a child
controller stopping after publication before activation, fresh-process resume,
loss of the receipt companion, precommit and committed3-to2 restore, fresh-root
admission, merge-like HEAD movement, unrelated Host preservation, foreign postimages,
unavailable selected controller identity, stale authority and wrong/missing
runtime rejection. An identical-tree HEAD change during runtime preflight refuses
under the held lease before either original-route CAS or activation. Activation
ports in those focused cases are TEST adapters;
these cases do not prove Linux package installation or hosted qualification.

Before adoption, retain and verify the actual published successor controller and
its installation/artifact proof independently of the old consumer installation.
Review and accept this proposal through the existing decision owner and ordinary
baseline promoter; review the public API delta and complete native CI. Then prove
physical published-package forward activation, cold resume and rollback in the
actual enrolled consumer. Do not infer any of these from source tests or registry
metadata. New version/SRI coordinates come from actual publication, never this
proposal.

Central's existing trusted consumer workflow is the physical Gen3 qualification
boundary: an enrolled consumer, exact current authority and immutable caller,
five verified installed packages, real26.11.1/pnpm11.20.0/Linuxx64, namespace
`docs-protocol-cohort-v3-qualification-receipt/v1` and receipt1. Evidence supports
qualification; genuine merged default-branch consumer checks own CANARY. This
proposal neither appends a Cohort nor enables a consumer or provider effect.

# Complete formatting input coverage

Status: source preparation; unpublished and unqualified. No consumer activation
or complete Platform/Runtime coverage is claimed by this implementation.

`quality.format-coverage` is an independent opt-in capability declared through
root configuration schema3. Existing root schemas1–2, source-coverage profiles1–4
and Stack native `format.paths` retain their existing contracts. The new profile
is `quality-format-coverage/v1`; schemas are the authority for its exact grammar.

Foundation owns full physical input classification through its existing census.
Only `.git` and `node_modules` are intrinsic technical boundaries. Explicit
format observation includes package generated directories, ignored files and root
metadata. Maintained roots classify the universe; they never limit discovery.
A missing/empty root, new unowned family, stale exact file, ambiguous route or
unsupported input fails. There is no generic ignore/outside category, extension
filter or hardcoded current file count.

Consumer owners supply actual maintained roots and exact retained, managed,
generated or validated-data authority routes. A tree's suffix family limits its
accepted authority inputs. A new unknown suffix must format or reject. Each
validator must be a contained direct Node script, optionally with `--check`;
pre/post hooks, recursive aliases and unrelated commands are refused. Authorities
must form the exact once-per-script blocking chain in an existing GateRunner
profile with concurrency1. This restriction grants no build, network, database,
provider, hook or source-write permission.

A declared readonly script and exit0 do not prove its semantics. Consumer
adoption must independently review its actual selection/effects and retain real
bad-input/noop-substitution rejecting witnesses for every claimed authority.
Missing safe native, support-file, lock or generated-output authority is a real
adoption blocker; format checking never invokes their producers automatically.

The static capability and `quality format --scope-only` validate classification,
route admission and literal-contract availability. Their informational diagnostic
explicitly says execution is absent. Full `quality format --consumer .` requires
the admitted Node runtime supported by Stack; there is no Bun fallback or new
worker loader. It invokes only the consumer-selected public Stack API after
negotiating `formatFilesContractVersion=1`. Stack0.1.1 lacks this feature and
rejects before invocation; no new released version is implied here.

Foundation passes every formatter candidate literally. Requested, validated and
attempted arrays and SHA256 digests over their canonical UTF8 JSON array must
match the expected set, every batch must complete successfully, and source bytes
must remain unchanged. Actual authority failures fail the same aggregate. The
original monotonic budget includes admission, census, literal execution,
authorities and source verification; children receive only its remaining time.
Existing cancellation, nested-runner refusal and physical process custody remain
with their owners. Uninterruptible reads cannot yield a late successful result;
this is cooperative checking, not a filesystem/effect sandbox.

The consumer's full `format:check` must bind this command and be reached from its
required gates. A direct native Stack command is an independent narrow scope,
never evidence of this complete closure. Final package/release qualification,
actual physical consumer installation and required native CI remain separate.
